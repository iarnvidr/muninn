# Muninn 0.2.29 — TikTok in Muninn, and the server/PWA foundation

### TikTok videos work through Muninn
- Open TikTok video, profile, feed, or search pages through the Muninn browser and proxy. TikTok is a first-class source beside YouTube, **not an embedded copy of the previous TikTok Saves website**.
- Capture For You, Following, profile, search, and related video information as Muninn feeds, with source context preserved where the page provides it.
- TikTok videos use the same background download, disk cache, keep/eviction policy, and offline-only player as YouTube. Muninn does not stream videos directly from TikTok during playback.
- Keep TikTok browsing credentials and proxy trust separate from YouTube. Actual personalized feeds depend on a valid signed-in TikTok browser session.

### Server and installable web app
- Run Muninn as a separate Rust server with a private Chromium capture browser and an installable PWA client; the existing macOS application remains supported.
- Open, queue, download, and play complete local video copies in the web client, including TikTok items. The PWA stores completed copies in local browser storage and will not play incomplete upstream streams.
- The remote preview uses owner-only authentication plus pairing, a sandboxed browser, and an image built and smoke-tested from the exact source commit.

### What has been verified
- Core TikTok capture fixtures, browser-to-Core smoke tests, web tests, and the Apple Silicon native candidate build and launch checks passed in CI.
- The owner-only server preview is deployed separately. Real signed-in TikTok account browsing, live video extraction, and physical-device offline playback still require acceptance tests; synthetic CI cannot prove those upstream/account-specific flows.

### Installation
Apple Silicon **prerelease**, ad-hoc signed and **not notarized**. In Muninn, use Settings → Muninn updates → **Stable and previews**. Stable-only installations are unaffected.
