# Updater release preparation

This repository currently has no published updater feed. The Tauri v2 updater format is a GitHub Releases `latest.json` containing `version`, `notes`, `pub_date`, and `platforms`; macOS Apple Silicon uses `darwin-aarch64` with `url` and `signature`. The updater payload is a gzip tar archive (`app.tar.gz`) of the exact app bundle plus its detached Tauri updater signature (`app.tar.gz.sig`). Do not substitute the app ZIP used for manual installation.

The workflow is manual-only and refuses non-main dispatches. It verifies the fetched existing tag commit equals both the dispatched protected-main `github.sha` and checked-out commit (not merely an ancestor), and requires the requested stable version to equal both `src-tauri/tauri.conf.json` and the built app bundle's `CFBundleShortVersionString`. After Tauri signing, it decodes the configured base64 minisign public key and base64 detached signature and runs the maintained `minisign -Vm` verifier against the actual archive before manifest generation or upload. Stable semantic versions only are accepted by `build/updater_release.py`; previews must not be offered to stable clients. Every artifact must be built, tested, and signature-verified before any eventual publishing. Keep bundled helpers, NOTICE files and license inventory intact; review `THIRD_PARTY_NOTICES.md`, `licenses/`, and the bundle's `Contents/Resources/licenses` before redistribution. Native macOS build signing currently uses ad-hoc code signing; that is distinct from the Tauri updater archive signature.

## Owner provisioning / publication boundary

No release was published or workflow executed for this task. Before dispatch, the owner must configure GitHub environment `muninn-release` with required reviewers and a deployment branch rule restricted to protected `main`. Provision environment secrets `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, and pin the corresponding public key in the application's updater configuration. Never put private signing secrets in repository-wide secrets or expose them to PR workflows. The owner generates and retains keys; none were read or generated here.

Owner manual procedure: (1) create the stable version tag and GitHub Release from a commit already on protected main; this workflow does not create tags/releases. (2) Dispatch this workflow from `main`, supplying matching stable version and existing `v<version>` tag, leaving publish false. (3) Review downloaded artifact contents, checksum, app smoke evidence, successful workflow minisign verification against the pinned public key and feed URL. (4) Confirm the configured keypair and environment protection, then explicitly dispatch again with publish true; environment approval gates the only write-capability job, which uploads solely to the already-existing release. The prepared feed points to `https://github.com/<owner>/<repo>/releases/download/<tag>/Muninn.app.tar.gz`; no active feed or release is claimed. Do not approve until macOS launch/playback and signing behavior are independently reviewed.
